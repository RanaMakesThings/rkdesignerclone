### 5. Visual Language For State And Reasoning

You mentioned wanting green up arrows and red down arrows. We will use them, but we must execute them with *clinical restraint*. If they are too bright or thick, the UI looks like a crypto exchange.

**Left Side: State Pills**
*   `Present`: Soft blue background (`bg-blue-50`), dark blue text (`text-blue-700`). No icon.
*   `Absent`: Soft red background (`bg-red-50`), dark red text (`text-red-700`). No icon.
*   *Why:* Blue is a standard, calm medical color for "noted/positive finding" without implying "good" (green) or "bad" (red). Red is standard for "denies/negative finding".

**Right Side: Reasoning Glyphs (The Arrows)**
Instead of standard bullet points, we use semantic typographic glyphs for the lists.
*   **Supports:** Uses a muted green up-arrow.
    *   *Glyph:* `↑` (Unicode U+2191)
    *   *Styling:* 12px, `text-emerald-600`, medium weight.
    *   *Example:* `↑ URI-like prodrome preceded cough`
*   **Against:** Uses a muted red down-arrow.
    *   *Glyph:* `↓` (Unicode U+2193)
    *   *Styling:* 12px, `text-rose-600`, medium weight.
    *   *Example:* `↓ No exertional dyspnea reported`
*   **Unknowns:** Uses an amber hollow circle or question mark.
    *   *Glyph:* `○` (Unicode U+25CB) or `?`
    *   *Styling:* 12px, `text-amber-600`, medium weight.
    *   *Example:* `○ Fever/chills severity`

*Design Note:* By using standard text glyphs rather than heavy SVG icons, the arrows act as scannable bullet points rather than overwhelming UI elements.

These are missing data points likely to change confidence or management.

### Suggested next question
Every candidate block should end with **one suggested next question**, but visually this should be subtle and standardized.

Format:
- `Next question: Any fever, chills, or measured temperature?`

However, only the **top-ranked candidate** should have its next question fully emphasized.  
For candidates #2 and #3, the next question can be present in lighter treatment.

Reason: the artifact should imply a prioritization of information gathering, not a barrage of simultaneous asks.

### Candidate count
Show **3 candidates only**.  
Not 5, not 7. More than 3 turns the right rail into a mini differential engine.

---

## Timeline implementation: bottom strip, internal block, or both?

Use **both**.

### Internal left-side timeline block
Purpose:
- textual interpretation
- supports the brief
- shows that chronology is part of structured understanding

### Bottom strip
Purpose:
- rapid scan
- story coherence
- “the model understood the sequence”

### Bottom strip structure
A horizontal strip with 4–6 event nodes connected by a line.

Example nodes:
- `URI-like scratchy throat`
- `Cough begins`
- `Burst pattern noted`
- `Night / lying down worse`
- `Yellow sputum in mornings`
- `Exertional dyspnea reported`

This should be compact and mostly monochrome, with one accent color for the current concern or latest event.

## 5. Visual Language For State And Reasoning

This is where we need to be very precise.

## Overall design principle
The visual language should be **quietly semantic**, not loud.  
It must support scanability without making the sheet look like a warning dashboard.

Think:
- low-saturation
- mostly grayscale
- one accent family for positive support
- one muted caution family for unknowns
- only very restrained negative color

---

## Should there be a green up arrow for support?

### Yes, but tiny and restrained
For **Supports**, use a **small upward-leaning support glyph**, but not a large arrow icon.

Best option:
- a tiny **green upward chevron or arrowlet** before each support bullet
- size around 10–12px
- muted green, not saturated

Why:
- It gives the user the directional semantics they asked for
- It makes the support/against distinction instantly legible
- It stays subtle enough to fit a clinical artifact

Alternative if even more restrained:
- use a green-tinted bullet dot rather than an arrow

My recommendation:
- **Supports = tiny muted green up-arrow glyph**
- only inside the right-side reasoning rail
- not on the left-side structured rows

This distinction matters. The left side is fact capture; the right side is reasoning.

---

## Should there be a red down arrow for against?

### Yes, but even more restrained than support
Use a **small muted red or oxblood down-arrow glyph** for **Against** bullets.

Important:
- not bright red
- not alarm red
- not large
- not triangle warning icon

Why:
- “Against” is not necessarily danger; it is diagnostic counterweight
- loud red would imply risk/severity rather than evidentiary friction

Recommended treatment:
- icon size same as support glyph
- color slightly desaturated brick/rose
- text remains neutral dark gray

So yes, use it—but keep it quiet.

---

## Should unknowns use amber question marks or something else?

### Yes, but use an outlined amber question marker, not a filled warning symbol
For **Unknowns**, use:
- a tiny outlined circle or rounded square with a `?`
- muted amber stroke
- very pale amber tint if any fill is used

Do **not** use:
- warning triangle
- exclamation mark
- bright yellow badge

Unknowns are not warnings; they are unresolved inputs.

Recommended:
- `?` glyph in muted amber, 10–12px
- followed by text in neutral gray

This creates a three-part logic:
- support = upward/fit
- against = downward/friction
- unknown = unresolved/question

That is exactly the kind of detailed symptom/differential semantics the user is asking for.

---

## Should these be arrows, bullets, left borders, pills, or tiny glyphs?

### Use tiny glyphs plus section labels; avoid extra pills
The best system is:

- **tiny glyphs for list items**
- **plain section headers** (`Supports`, `Against`, `Unknowns`)
- **no pills for every bullet**
- **no thick left borders per subsection**

Why:
- bullets need directional semantics
- section headers already tell the bucket
- additional pills or borders would make the rail heavy and widget-like

### Specific recommendation
- Supports: tiny muted green up arrow
- Against: tiny muted red down arrow
- Unknowns: tiny outlined amber question glyph

And that’s it.  
No additional iconography.

---

## Exactly how restrained or prominent should they be?

### Restraint rules
- icons should never be larger than the first text line
- icons should not be the highest-contrast element
- diagnosis title stays visually dominant
- confidence and movement are secondary
- support/against/unknown glyphs are tertiary cues

In practical terms:
- title text: strongest
- body text: medium
- pills/chips: medium-light
- evidence/trace: light
- glyphs: light-medium

The user should feel the semantics immediately, but not feel “designed at.”

---

## How should `present`, `absent`, and `unresolved` look?

These states apply to the **left-side fact rows**, so they need a different visual language than the right-side reasoning glyphs.

### `present`
- pill shape
- dark text on very light neutral fill, or white text on charcoal fill
- if using the screenshot’s black pill, soften slightly to deep charcoal rather than pure black
- no green here

Reason: presence is not “good.” It is simply present.

### `absent`
- pill shape
- medium gray text on light gray fill
- lower visual weight than present

Reason: absent should still be legible but visually quieter.

### `unresolved`
- pill shape
- warm gray or very pale amber-tinted fill
- dark gray text
- subtle dotted or dashed border optional

Reason: unresolved should stand apart from absent without looking like a warning.

### State hierarchy
- `present` = strongest
- `unresolved` = medium
- `absent` = lighter

This gives a clean reading order.

---

## Additional row-level visual semantics

### Key negatives on the left
Do not add red down arrows in the left-side rows.  
Just let the category label **Key Negatives** do the semantic work.

Why:
- otherwise the left side becomes symbol-heavy
- the left side should feel like structured charting, not argumentative logic

### Workup rows
For missing objective data, use `unresolved` or `not yet assessed` rather than `absent`.

Important distinction:
- `absent` = symptom/feature denied
- `not yet assessed` = objective data missing

This is clinically and visually important.
