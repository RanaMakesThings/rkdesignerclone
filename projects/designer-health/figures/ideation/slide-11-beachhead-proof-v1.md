# Slide 11 Ideation — Beachhead Proof v1

## Brief read

Slide 11 is the beachhead-definition slide.

- slide `10` says the product creates real throughput value
- slide `11` says where Vox should prove that value first
- slide `12` then says why the team can execute the plan

So this slide should not read as market sizing or specialty selection.
It should read as a disciplined first-market definition:
pick the settings where proof happens fastest.

## Current family read

The packet's core family is right:

- one dominant beachhead profile object
- three qualifying conditions attached to it
- example settings used only as supporting evidence
- one compact proof scorecard

The main design risk is not a missing idea.
It is slipping back into consulting syntax:
funnel, filters, scorecards, or specialty taxonomy.

## Codex directions

### 1. Beachhead Profile Hero + Proof Scorecard

- one large blue profile card:
  `High-throughput groups with simple deployment`
- three qualifying conditions attached as rails, tags, or side labels
- example settings shown quietly around it as examples of the profile
- proof scorecard on the right

Why it works:

- makes the profile the thesis
- keeps the slide cross-specialty
- gives the proof panel a clean secondary role

Main risk:

- if the example settings get too prominent, the slide starts reading like a
  market map

### 2. Shape-Not-Specialty Field

- one central blue profile object
- faint surrounding example settings as contextual satellites
- very sparse proof card integrated below or to the right
- small line:
  `A profile, not a specialty`

Why it works:

- the profile point becomes emotionally obvious
- feels more premium and less diagrammatic

Main risk:

- can become too abstract if the qualifiers are not explicit enough

### 3. Qualifying-Conditions Strip

- horizontal strip anchored by:
  `visible visit pressure`
  `simple buying`
  `low deployment friction`
- one quiet group of example settings beneath or after the strip
- proof scorecard on the right

Why it works:

- makes the qualification logic explicit
- gives the viewer a very fast checklist read

Main risk:

- easiest path into a filter/funnel/consulting slide

## Model-backed ideation

The packet already made the strategic correction:
the wedge is not primary care.
The model pass should stress-test only the expression.

The provider-backed `figures:ideate` wrapper was attempted first, but it failed
because the Claude response was not strict JSON.
Direct Claude ideation and Gemini concept generation were still collected and
used for synthesis.

### Claude Sonnet 4.6 themes

- strongest families:
  - proof column
  - field with anchor
  - lit condition strip
- Claude's final judgment:
  - best overall: proof column
  - strongest visual alternative: field with anchor

What is useful from that:

- Claude is pushing toward a more memo-like investor-reading structure than the
  original card-led direction
- the most important useful correction is placement:
  example settings should probably live as a quiet footer group, not as
  satellites, because satellites make the slide read like specialty selection
- the profile point gets stronger when the conditions read as criteria before
  the examples appear

### Gemini rendering themes

First Gemini image pass for the profile-hero concept landed.

What is useful from that:

- the profile-card family is viable
- the concept does read quickly
- but the current comp is too literal and slightly too spreadsheet-like on the
  proof panel
- prompt leakage near the top confirms the family still needs a cleaner
  execution branch before promotion

## Synthesis

The slide should not ask:

- which specialty first?

It should ask:

- what operating profile gives Vox the shortest path to proof?

That means the hero object must be a profile, not a named setting.
Example settings are valid only if they visibly behave like evidence, not like
the answer itself.

## Recommendation

Lead concept for the next render/composition pass:

### Beachhead Profile Hero + Proof Scorecard

- one dominant beachhead profile card
- three qualifying conditions visibly attached
- example settings remain faint and secondary, ideally as a footer group rather
  than orbiting satellites
- proof scorecard sits to the right as the practical pilot frame

This is the clearest way to preserve both halves of the message:

- cross-specialty first-market profile
- real pilot proof discipline
